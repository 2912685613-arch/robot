# 参数与响应可视化调试台

当前调试台用于 **ArUco 对接专用控制器**：调整高度位置/速度双环、XY阻尼、航向保持、限速、到位条件和失效恢复参数。它不替代手动 `xyz/dep/yaw` 控制器，也不会把手动模糊PID开关套用到自主对接。

界面使用本地浏览器，包含参数分组、运行控制、实时曲线、响应指标、试验比较和CSV/YAML导出。不依赖rqt、rosbridge、Flask、外部图表CDN；网页资源全部在工作空间中。

## 启动

本次为motion增加了遥测话题和参数重载服务。首次使用或修改C++后先编译：

```bash
cd /home/gjx/robot/gazebo_catkin_ws
source devel/setup.bash
cmake --build build --target motion -j2
```

先关闭旧motion/旧仿真，按原来的方式启动动态仿真：

```bash

```

另开一个终端启动调试台，不会再启动一套Gazebo，也不会自动发运动命令：

```bash
cd /home/gjx/robot/gazebo_catkin_ws
bash src/gazebo_launch/tuning_dashboard.sh
```

浏览器访问：

```text
http://127.0.0.1:8765
```

若使用VS Code远程/WSL，可以将8765端口转发到本机后在本机浏览器打开。服务只监听本机127.0.0.1。端口被占用时用 `--port 8766` 并打开对应地址。

## 不启动仿真，只看看界面

```bash
bash src/gazebo_launch/tuning_dashboard.sh --demo
```

此模式使用演示曲线，页面顶部明确显示DEMO，不连接ROS和机器人。可以试改参数、应用、开始/结束记录及导出。演示模型只是验证界面，不代表Gazebo的动力学效果，也不能用来调好真实控制器。

## 一次调参试验的步骤

1. 等待顶部显示已连接，参数版本显示v1或当前节点版本。
2. 左侧修改参数，如 `position_kp`、`velocity_kp`、`velocity_ki`、`max_speed`。修改框会突出显示；此时尚未改变机器人。
3. 点击“应用参数并停止对接”。界面会发送st并调用motion重载服务，节点验证成功后重建专用控制器、清空对接历史并返回**实际生效参数**。版本号增加。单纯修改ROS参数服务器不足以改变已在内存中的控制器。
4. 若要可比的初始条件，点击“重置机器人”。明确执行世界坐标 `(0,0,-0.1)`、零姿态/速度，然后暂停。它是Gazebo准备动作，不是视觉自主归位；标记位置保持原样。初始位置与这个默认值不一致时不要随意使用此按钮。
5. 点击“对接并记录”。界面恢复物理，等待停顿后产生的新定位，再发送dock，并开始一次独立记录。不依赖另一个终端的键盘命令。
6. 看状态和曲线：XY_ALIGN、APPROACH、HOLD；失效时会显示等待/制动/LOST_STOP。
7. 观察保持阶段后，点击“停止并暂停”。试验自动结束，保存到日志目录；也可“仅开始记录/结束记录”，这些按钮只改变记录，不改变运动模式。
8. 修改一个或一组参数，重复同样初始条件；在试验对比表点击“对比曲线”或“复用参数”。复用只是填入输入框，不会自动应用。

停止按钮会发送st并暂停世界；遥测掉线时也保留可点击状态，可尝试停止，但节点已经不在线时不能承诺命令收到。关闭浏览器或调试台只停止观察/记录，**不会自动停止机器人**；离开前先点击停止或在原脚本中输入st/quit。

“恢复仿真”只恢复物理，不发dock；“冻结图表”只停图表重绘，不停机器人。不要混淆。

## 参数是否真正生效

涉及的ROS接口：

```text
/robot1/motion/docking/                       参数命名空间
/robot1/motion/reload_docking_config          std_srvs/Trigger，确认重载
/robot1/motion/docking_telemetry              std_msgs/String，结构化JSON遥测
/robot1/cmd_message                          dock/st 命令
/robot1/pwm_message                          四电机实际发布指令
```

遥测包含motion实际持有的完整配置和递增revision，网页的“读取生效值”读取的是遥测，而不是把输入框或参数服务器内容当作已经生效。修改其他终端的参数服务器值后，还必须经过重载服务才会生效。

参数应用是**停止后重载**，不会在运行中直接换增益并保留旧积分。需要再次点击开始对接。非法参数在网页后端和运动节点分别检查；服务拒绝时保留旧控制器，界面报错。

通过界面应用只改变本次运行的参数服务器和运动节点，不会自动覆盖源码的 `config/docking_control.yaml`。需要长期保留时，点击右上“导出参数”，再有意地用导出的YAML更新启动配置。每次记录的JSON也保存当次参数快照，方便恢复。

## 曲线和量纲

- **高度响应**：`distance=-marker_body_z`，目标为 `-target_z`，默认0.15m；是机体原点与标记沿机体Z轴的间距，不是光心距离，也不是机器人外壳净空。
- **X/Y对准**：标记在机体系中的相对X/Y，目标0m。
- **航向响应**：当前yaw减去dock时捕获目标yaw的最短角度差，目标0°。此系统主要做抗漂移保持，若本次没有显著航向阶跃，上升时间/超调百分比显示“—”是正常的。
- **垂直速度**：目标vz和机体系实际vz，m/s。限速是目标值，不是物理实际速度硬约束。
- **推进器**：从pwm话题收到的四个输入指令，0～100；不是实际牛顿值。输入过期时断线显示。

指标使用ROS源采样时间；界面心跳和墙钟刷新不能增加有效采样。暂停、重复源图像、丢失期间的默认零值不会被当作新的稳定反馈。

高度指标从这次记录首次进入APPROACH/HOLD时开始，不把此前XY对齐耗时误当成高度上升时间。X/Y/航向从记录的第一个有效采样开始。

## 指标怎么计算

设本段第一个有效测量为 `y0`，固定目标为 `r`，方向 `d=sign(r-y0)`，初始幅值 `A=abs(r-y0)`。

```text
超调量 = max(0, max[d × (y-r)])
超调百分比 = 超调量 / A × 100%
上升时间 = 首次到达90%响应的时间 − 首次到达10%响应的时间
```

因此下降过程在目标高度以下的越界也会计为超调。初始幅值近零时不计算百分比，避免除零或误导。

调节时间是最后一次超差/采样缺口之后进入误差带的起点（相对该通道的起点），并要求尾段一直在带内且达到 `settle_time`。实时值标为暂定；后续再次超差会撤销，结束记录后才是本段观测结论。

尾段平均误差取最后约0.5～2秒有效样本的 `目标−测量` 均值，界面同时给出RMSE。**尚未稳定时，这个数不能被称为真正稳态误差。**

源采样相邻间隔超过0.6秒或存在无效数据时，不跨缺口插值10%/90%时间；指标标记“有缺口，仅供参考”。仿真时间回退或有效参数版本变化，会结束本段记录，避免把两次不同试验混在一起。

这些是当前非线性、带限速、状态切换的闭环任务观测指标。减小上升时间不一定更好：应同时比较超调、实际速度、HOLD稳定性、数据有效性和饱和情况。

## 数据保存与比较

```text
logs/tuning_dashboard_<时间>/
    trial_<id>.json      完整采样、参数快照、指标与结束原因
```

页面保留本次调试台进程最近12次试验用于比较；文件会保留在磁盘。重启调试台后不自动加载旧文件。当前单段最多记录约30分钟（18000条心跳），到上限自动保存。

CSV包含ROS时间、源时间、有效性、位置、航向、速度、控制力及参数版本，UTF-8 BOM方便表格软件打开。参数YAML和CSV可以分别下载。记录没有严格同步相机与ModelStates；与Gazebo真值的毫米级差异不能直接当作真实传感器精度。
